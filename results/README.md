# Результаты проверок

Текущая конкурсная конфигурация и полный ROS-прогон: [v04/INDEX.md](v04/INDEX.md) и [отчёт](../docs/CHECKER_V04_RU.md). Таблицы ниже описывают историю до 0.4.

В выпуске 0.4.1 локальные пути и служебные названия в копиях исторических журналов приведены к нейтральному виду. Числа, условия опытов и контрольные суммы исходных данных сохранены. Старые SHA отдельных файлов относятся к их первоначальным байтам; редакционно обработанные копии не являются исходными запечатанными журналами. `historical-work/` обозначает прежнее дерево экспериментов, а не обязательный каталог текущего проекта. Для повторения используйте переносимые команды из инструкции жюри.

# Как читать результаты

Текущий фиксированный кандидат: `validation_hypotheses/metrics.json`, `audit_hypotheses/metrics.json`, `ros_humble_v03.json`, `properties/properties.json`, `speed_stress_final.json`. В 0.3.1 позиционные метрики кандидата и `audit_joint` (траектория E-02) пересчитаны по oracle 3.6. Speed/runtime поля скопированы из исходного replay; происхождение записано в `rescore_provenance`. `reference_order_v36` содержит аудит изменения; прежние отчёты сохранены в неизменном релизе 0.3.0. `hairpin_builder_reproduction_v36.json` подтверждает тот же CSV после исправления, исходный builder-отчёт сохранён отдельно. Полная методика и таблицы — `docs/ACCURACY_RU.md`. `official_final` — контроль без терминальных дополнений: нет абсолютной инициализации, поэтому ENU-ошибка не определена.

`baseline_*` воспроизводит исходный B6 без нового конвейера, на исходной сетке и с другим исключением старта. Прямо сравнивать его число с итоговой скоростью после3с без согласования выборок нельзя.

Остальные каталоги сохранены как история разработки. `validation_extended` содержит неудачный выбор направления. `validation_loop` — раннюю несглаженную карту; `validation_loop_smooth`, `validation_scaled`, `validation_aligned_scaled` — абляции до совместной привязки антенн. `audit_final` — прежний строгий вариант с3/4 успешными инициализациями; его pooled-position RMSE не сопоставим с итоговым4/4.

**Недействительная пространственная метрика:** старый `validation_official/metrics.json` ошибочно сравнивал `odom_relative` с ENU. Его километровые значения не имеют смысла и не доказывают улучшения. Ошибка исправлена в scorer; этот артефакт сохранён только для прозрачной истории. Итоговый отчёт его не использует.

JSON `speed_master` — историческое имя скалярного выхода, сопоставленного с основным скоростным эталоном; физическая поправка плеча выключена. Явные `speed_vs_master`, `speed_vs_rover`, `gnss_speed_disagreement` доступны в окончательных файлах. `speed_bogie` и `speed_master` при выключенной поправке совпадают.
